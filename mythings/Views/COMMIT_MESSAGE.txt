Fix: Prevent item category from reverting after edit due to iCloud sync race condition

This commit fixes a critical bug where editing an item's category would appear
to save, but then revert back to the original category after a few seconds.

Root Cause:
- iCloudSyncManager's mergeItemChanges() was unconditionally overwriting local
  items with cloud versions, without checking which version was newer
- ContentView's sync success handler blindly reloaded all items from disk,
  discarding any recent in-memory edits
- This created a race condition where older cloud data would overwrite newer
  local edits during sync operations

Changes Made:

1. iCloudSyncManager.swift - Timestamp-based merge logic
   - Added timestamp comparison in mergeItemChanges()
   - Only merge cloud version if cloudUpdatedAt >= localUpdatedAt
   - Keep local version when it's newer than cloud version
   - Added detailed logging for merge decisions

2. ContentView.swift - Preserve recent edits
   - Added logic to preserve items edited in last 10 seconds
   - Restore recently edited items after loadItemsFromLocal()
   - Only restore if recent version is actually newer
   - Re-save to disk to persist preserved changes

3. AddItemView.swift - Enhanced logging and timestamp refresh
   - Ensure updatedAt is set to current moment when saving
   - Added detailed logging for category changes
   - Log category ID and timestamp for debugging

4. Documentation
   - Created FIX_CATEGORY_REVERT_ISSUE.md with comprehensive analysis
   - Documented root cause, solution, testing steps, and prevention guidelines

Impact:
- Category edits now persist correctly across sync operations
- All field edits (name, brand, price, etc.) are protected from overwrites
- Implements "last write wins" conflict resolution strategy
- Maintains data consistency across multiple devices

Testing:
- Verified basic category changes persist after 10+ seconds
- Tested rapid category changes (multiple edits in succession)
- Confirmed multi-device sync works correctly
- Verified console logs show proper merge decisions
